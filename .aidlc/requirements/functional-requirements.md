# 功能需求文档 - 优惠券发放与核销中心

## 概述

本文档定义了优惠券发放与核销系统的功能需求，共包含11项功能需求，涵盖用户认证与自助注册、活动管理、领券核销、AI推荐、风控安全等核心功能。

## 功能需求列表

### FR-001: 用户认证与角色管理

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-001 |
| **需求名称** | 用户认证与角色管理 |
| **描述** | 系统提供用户登录认证，按角色区分权限 |
| **角色** | 所有角色 |
| **前置条件** | 系统预置至少6个账号（admin, operator, verifier, customer_a, customer_b, customer_c） |
| **业务规则** | BR-001: 每个账号绑定唯一角色<br>BR-002: 登录后按角色展示不同页面 |
| **正常结果** | 用户登录成功，进入对应角色首页 |
| **异常处理** | 凭据错误返回401；无权限访问返回403 |
| **优先级** | P0 |
| **来源** | 项目需求 + 4角色要求 |
| **验收标准** | AC-001: 6个账号可正常登录<br>AC-002: 不同角色看到不同导航菜单 |

### FR-002: 优惠券活动管理

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-002 |
| **需求名称** | 优惠券活动管理 |
| **描述** | 运营人员创建、编辑、查询优惠券活动 |
| **角色** | operator |
| **前置条件** | 已以运营人员身份登录 |
| **业务规则** | BR-003: 活动包含名称、面额、库存、有效期、每用户限领数<br>BR-004: 库存 > 0 且 ≤ 100000<br>BR-005: 每用户限领数 ≥ 1<br>BR-006: 结束时间 > 开始时间 |
| **正常结果** | 活动创建成功，状态为草稿/进行中 |
| **异常处理** | 参数不合法返回400；库存设置异常返回400 |
| **优先级** | P0 |
| **来源** | 项目需求三.1 |
| **验收标准** | AC-003: 可创建完整活动<br>AC-004: 非法参数被拒绝<br>AC-005: 活动列表正确分页 |

### FR-003: 用户领券（含原子库存扣减）

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-003 |
| **需求名称** | 用户领券（含原子库存扣减） |
| **描述** | 用户领取优惠券，系统执行原子库存扣减，保证不超发 |
| **角色** | customer |
| **前置条件** | 活动进行中且库存 > 0 |
| **业务规则** | BR-007: 库存原子扣减（CAS/悲观锁）<br>BR-008: 每人不超过限领数<br>BR-009: 同一用户同一活动重复领取返回"已领取" |
| **正常结果** | 领券成功，返回券码和详情 |
| **异常处理** | 库存不足 → "已抢光"；超限 → "已达领取上限"；重复 → "已领取" |
| **优先级** | P0 |
| **来源** | 项目需求三.2 |
| **验收标准** | AC-006: 库存N时N个并发请求全部正确处理<br>AC-007: N+1并发只有N个成功<br>AC-008: 重复领取正确拒绝 |

### FR-004: 优惠券核销（幂等）

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-004 |
| **需求名称** | 优惠券核销（幂等） |
| **描述** | 核销人员验证并核销优惠券，支持幂等 |
| **角色** | verifier |
| **前置条件** | 券状态为"已领取"且未过期 |

| **异常处理** | 过期 → "券已过期"；已核销 → "已核销"（幂等返回）；不存在 → 404 |
| **优先级** | P0 |
| **来源** | 项目需求三.3 |
| **验收标准** | AC-009: 重复核销返回一致结果<br>AC-010: 过期券被拒绝<br>AC-011: 不同业务单号不冲突 |

### FR-007: AI异常检测（风控）

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-007 |
| **需求名称** | AI异常检测（风控） |
| **描述** | 领券时评估用户行为风险，返回评分与决策；AI不可用时降级为规则引擎 |
| **角色** | customer（领券触发）, operator（审核） |
| **前置条件** | 风控模块启用 |
| **业务规则** | BR-016: 风险评分0-100<br>BR-017: 评分 < 30放行，30-70人工审核，>70拦截<br>BR-018: AI不可用时降级为规则引擎（频率+时段+数量）<br>BR-019: 短时间高频领取触发拦截 |
| **正常结果** | 低风险放行，高风险拦截并记录 |
| **异常处理** | AI不可用 → 规则引擎接管 |
| **优先级** | P0 |
| **来源** | 项目需求三.6 |
| **验收标准** | AC-016: 10秒内50次领取触发风控拦截<br>AC-017: AI降级后规则引擎仍生效 |

### FR-011: 用户自助注册

| 字段 | 内容 |
|------|------|
| **需求编号** | FR-011 |
| **需求名称** | 用户自助注册 |
| **描述** | 普通用户、核销人员、运营人员可在各自站点自助注册账号；管理员不提供注册入口 |
| **角色** | customer、operator、verifier（admin 除外） |
| **前置条件** | 无需登录；注册角色由所在站点决定，不由请求方自选 |
| **业务规则** | BR-026: 仅 customer/operator/verifier 可自助注册，admin 一律拒绝<br>BR-027: 账号名 3-32 位字母数字下划线且全局唯一（大小写不敏感）<br>BR-028: 密码至少 8 位且同时包含字母和数字，仅存 bcrypt 哈希<br>BR-029: 注册成功即建立会话，角色以服务端写入值为准<br>BR-030: 配置员工注册码后，operator/verifier 注册必须提供正确注册码 |
| **正常结果** | 账号创建成功并直接进入对应角色站点，注册动作写入审计日志 |
| **异常处理** | 角色为 admin 返回 403；账号重复返回 409；账号或密码不合规返回 400；注册码错误返回 403 |
| **优先级** | P1 |
| **来源** | 2026-07-30 用户新增需求 |
| **验收标准** | AC-024: 三种角色均可注册成功并登录<br>AC-025: 注册 admin 被拒绝且不创建账号<br>AC-026: 重复账号名被拒绝 |

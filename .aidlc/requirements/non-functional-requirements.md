# 非功能需求文档 - 优惠券发放与核销中心

## 概述

本文档定义了系统的非功能性需求，包括数据库可扩展性、前端交互体验、并发安全、AI降级、安全性、性能和可观测性等方面的要求。

## 非功能需求列表

### NFR-001: 数据库可扩展性 ⭐重点

| 字段 | 内容 |
|------|------|
| **需求编号** | NFR-001 |
| **需求名称** | 数据库可扩展性 |
| **描述** | 数据库设计必须支持未来扩展，包括新增券类型、新增规则、多租户等 |
| **类别** | 可扩展性 |
| **优先级** | P0 |
| **具体要求** | 1. 使用迁移工具管理schema变更（如Prisma Migrate）<br>2. 关键字段使用JSONB存储可扩展配置<br>3. 券类型使用策略模式便于新增<br>4. 风控规则使用规则表而非硬编码 |
| **验收标准** | 新增一种券类型（如折扣券）只需新增配置，不修改核心表结构 |
| **测量指标** | 新增业务功能时，数据库结构变更次数 ≤ 1 |
| **约束** | 使用PostgreSQL数据库，支持JSONB字段 |

### NFR-002: 前端交互体验 ⭐重点

| 字段 | 内容 |
|------|------|
| **需求编号** | NFR-002 |
| **需求名称** | 前端交互体验 |
| **描述** | 前端设计必须美观、流畅、现代化 |
| **类别** | 用户体验 |
| **优先级** | P0 |
| **具体要求** | 1. 使用现代化UI框架（React + Ant Design + Tailwind CSS）<br>2. 所有操作有加载、成功、失败状态反馈<br>3. 空状态有引导提示<br>4. 移动端响应式适配<br>5. 领券动画效果（抽取/翻转）<br>6. 统计面板使用ReCharts图表<br>7. Toast通知 + 骨架屏加载<br>8. 暗色模式支持 |
| **验收标准** | 核心操作流畅，动画60fps，移动端布局不崩溃 |
| **测量指标** | 页面加载时间 < 2秒，动画帧率 ≥ 60fps |
| **约束** | 支持现代浏览器（Chrome 90+, Firefox 88+, Safari 14+） |

### NFR-003: 并发安全

| 字段 | 内容 |
|------|------|
| **需求编号** | NFR-003 |
| **需求名称** | 并发安全 |
| **描述** | 库存扣减并发场景下数据一致性 |
| **类别** | 可靠性 |
| **优先级** | P0 |
| **具体要求** | 使用数据库行级锁或CAS（Compare-And-Swap）保证库存不超发 |
| **验收标准** | 库存为1时，50并发请求只有1个成功 |
| **测量指标** | 在高并发场景下，数据不一致率为0 |
| **约束** | 使用PostgreSQL的行级锁或CAS机制 |

### NFR-004: AI降级与可追溯

| 字段 | 内容 |
|------|------|
| **需求编号** | NFR-004 |
| **需求名称** | AI降级与可追溯 |
| **描述** | AI功能不可用时的降级策略 |
| **类别** | 可用性 |
| **优先级** | P1 |
| **具体要求** | 1. Bedrock不可用 → 推荐降级为热门推荐，风控降级为规则引擎<br>2. 所有AI调用记录输入/输出/耗时/模型<br>3. 超时设置10s（模型列表）/60s（对话） |
| **验收标准** | 关闭Bedrock端点后系统核心功能仍可用 |
| **测量指标** | AI服务不可用时，系统降级时间 < 5秒 |
| **约束** | 遵循bedrock.service.txt的双路径设计 |

### NFR-005: 安全性

| 字段 | 内容 |
|------|------|
| **需求编号** | NFR-005 |
| **需求名称** | 安全性 |
| **描述** | 系统安全要求 |
| **类别** | 安全性 |
| **优先级** | P0 |
- **具体要求**:
  1. JWT Token认证，有效期24小时
  2. 角色权限中间件，防止越权访问
  3. API输入校验，防止恶意输入
  4. SQL注入防护（ORM参数化查询）
  5. XSS防护（前端输入转义）
  6. 密码哈希存储（bcrypt算法）
  7. 审计日志记录所有关键操作

- **验收标准**:
  1. 未经认证无法访问API
  2. 不同角色无法访问未授权功能
  3. 恶意输入被正确过滤
  4. SQL注入攻击无效
  5. XSS攻击无效

- **测量指标**:
  1. 认证失败率 < 0.1%
  2. 权限检查覆盖率100%
  3. 安全漏洞扫描通过率100%

### NFR-006: 性能

| 字段 | 内容 |
|------|------|
| **需求编号** | NFR-006 |
| **需求名称** | 性能 |
| **描述** | 系统性能指标 |
| **类别** | 性能 |
| **优先级** | P1 |
- **具体要求**:
  1. 领券接口P99 < 500ms
  2. 核销接口P99 < 200ms
  3. 统计查询 < 1s
  4. AI推荐 < 5s
  5. 页面加载时间 < 2s
  6. API响应时间P95 < 1s

- **验收标准**:
  1. 核心接口响应时间满足要求
  2. 高并发场景下系统稳定
  3. 数据库查询优化良好

- **测量指标**:
  1. 接口响应时间分布
  2. 系统吞吐量（QPS）
  3. 并发用户支持数

### NFR-007: 可观测性

| 字段 | 内容 |
|------|------|
| **需求编号** | NFR-007 |
| **需求名称** | 可观测性 |
| **描述** | 系统日志和监控 |
| **类别** | 可维护性 |
| **优先级** | P1 |
- **具体要求**:
  1. 结构化日志（请求ID、用户、操作、耗时）
  2. 关键操作审计日志
  3. 错误告警（Slack/邮件通知）
  4. 性能监控（CPU、内存、磁盘）
  5. 业务指标监控（领取数、核销数、风控拦截数）
  6. 健康检查接口

- **验收标准**:
  1. 问题可快速定位
  2. 系统状态可实时监控
  3. 异常可及时告警

- **测量指标**:
  1. 平均故障恢复时间（MTTR）
  2. 监控覆盖率
  3. 告警准确率

## 非功能需求分类汇总

### 优先级分布
- **P0（必须满足）**: NFR-001, NFR-002, NFR-003, NFR-005 (4项)
- **P1（应该满足）**: NFR-004, NFR-006, NFR-007 (3项)

### 类别分布
- **可扩展性**: 1项 (NFR-001)
- **用户体验**: 1项 (NFR-002)
- **可靠性**: 1项 (NFR-003)
- **可用性**: 1项 (NFR-004)
- **安全性**: 1项 (NFR-005)
- **性能**: 1项 (NFR-006)
- **可维护性**: 1项 (NFR-007)

## 技术约束

1. **数据库约束**: 必须使用PostgreSQL，支持JSONB字段
2. **前端约束**: 必须支持响应式设计，适配移动端和桌面端
3. **AI集成约束**: 必须实现降级策略，保证AI不可用时系统可用
4. **安全性约束**: 必须实现完整的认证授权机制
5. **部署约束**: 单机部署，前后端分离

## 验收测试方法

1. **负载测试**: 模拟高并发场景，验证系统性能
2. **压力测试**: 验证系统极限承载能力
3. **安全测试**: 渗透测试、SQL注入测试、XSS测试
4. **兼容性测试**: 不同浏览器、不同设备测试
5. **可用性测试**: AI服务不可用时的降级测试
6. **可扩展性测试**: 新增业务功能时的扩展测试
